# Project OS 产品约定

## 用户和目标

面向用 AI 持续开发项目、频繁切换会话或执行工具的人。用户通常把本仓库链接发给 AI，要求“应用到当前项目”。接入成本应由 AI 承担，用户不必理解整套模板或人工搬运派工内容。

期望结果：换会话后能继续；目标不被改写；重要结论有证据；多个执行者的改动能被接回；使用者只处理真正需要其判断的问题。

## 当前产品范围

- 给现有项目增量接入，也支持空项目；保留业务事实、已有治理和 Git 身份。
- 一份事实来源映射、短入口与按需模板。
- 目标身份、文件冲突、接入幂等性和声明证据的机器检查。
- 工具中性的委派 / 交付 / 验收 / 恢复合同。
- AI 可执行的治理试验与用户能读懂的简短回执。
- 中文、英文 README，公开示例不携带任何真实项目资料。

## 不在当前实现范围

没有通用 Agent 调度服务、自动调用模型、自动发布业务代码、持续监控或语义真伪判定器。接入工具不会读取凭据、修改全局 AI 配置或自动安装所有技能。真实业务验收仍依赖相应测试和使用证据。

## 如何判断有效

关注新会话能否找对目标与下一步、过期事实是否被识别、未验证交付是否被拒绝冒充完成、恢复是否避免重复工作，以及人工纠偏和文档维护负担是否下降。按 [试验](../03_DELIVERY/GOVERNANCE_TRIAL.md) 留证，不以文档数量或机器检查绿色代替效果。

## 设计约束

先验证最关键不确定性，再扩展工程。保留模型自主判断的空间，用明确目标、必要边界与可核查结果约束工作。工具与模型可替换；治理不固化“哪家模型永远更适合指挥”。
