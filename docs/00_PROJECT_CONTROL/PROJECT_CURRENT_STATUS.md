# 当前状态

更新：2026-09-26 · 工具包版本：1.2.1

## 当前目标

让用户把仓库链接交给 AI 后，能将治理增量接入现有项目；通过 AI 可执行的检查与接手试验，观察它是否减少失误和人工协调。

## 实现与验证

v1.2.1 仅将文档盘点与清理改为用户明确请求后启动，按请求范围执行；移除接入、任务收尾、交接、方案替代及冲突等自动触发与清理询问。同步中英文入口、接入指南和新安装 RULES，归类、压缩、归档、提问边界及检查器行为不变。

本版 43 项本地回归、结构检查及四种请求的独立规则接手检查通过，范围见 [v1.2.1 验证记录](../05_HANDOFF/evidence/2026-09-26-v1.2.1-validation.md)。

v1.2.0 增加文档生命周期、用户提问边界和只读 inventory；其自动启动规则现已被 DEC-013 替代。此前 43 项本地回归与两个独立合成接手案例的环境、结果见 [v1.2 历史验证记录](../05_HANDOFF/evidence/2026-09-26-v1.2-validation.md)，不能用它们证明本版的主动唤醒行为。

公开名称为 **Awoo Vibe Coding Governance**，母仓库身份检查兼容新旧 URL，安装文件名和 schema 保留。历史更名验证见 [v1.1.1 记录](../05_HANDOFF/evidence/2026-09-25-v1.1.1-validation.md)。

v1.1.0 已实现增量接入工具、单一事实来源映射和执行合同，并完成一次独立 AI 接入、一次隔离中断接手，保留了原业务内容与 Git 身份。这些是此前版本的演练结果，具体环境与局限见 [v1.1 验证记录](../05_HANDOFF/evidence/2026-09-25-v1.1-validation.md)。

尚未验证真实跨工具进程恢复和长期使用收益。机器检查通过不等于业务验收，source 仓库没有活动业务任务。

## 已确认的设计

- 源工具包与目标项目身份分离，接入保留目标 Git、已有文档和业务内容。
- 一项事实只维护一处；当前状态、交接和历史承担不同职责。
- 模型与 CLI 可替换；委派通过基线、写入归属、回执和验收证据接回。
- 文档和机器检查本身不能证明治理有效，需要独立接手与异常演练。
- 文档盘点与清理仅由用户明确请求唤醒；唤醒后先查证据，仅在意图、独有约束或授权无法裁定时提问，等待期间保留原文并继续独立工作。

## 待验证假设

增量接入和精简入口能减少真实项目里的用户纠偏与重复工作。当前尚无一段时间的使用数据，不能宣称已经提升开发效率。

## 下一步

在真实项目中使用并记录具体失败、维护负担和人工介入。只从观察到的问题演进，不继续扩展空模板。
