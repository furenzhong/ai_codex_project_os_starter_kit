# 文档生命周期 / Document lifecycle

开发过程会产生调研、功能调整、阶段计划和方案草稿。它们当时有用，不代表下次会话仍应按它们做事。治理的目标是让 AI 用较少阅读找到当前依据，同时保住不能重新推导的约束、未决问题和历史原因。文件数下降不是验收标准。

## 先判断是否值得留下

能从代码、命令或当前状态廉价重建的过程描述，不必每次另写总结。影响下一次决策、无法轻易重建的用户要求、取舍原因、失败观察和中断现场才需要持久保存。优先更新已有来源；不要同时创建“清理报告”“整理报告”和另一份当前状态。

## 按用途决定读取范围

| 材料 | 用途 | 读取时机 | 工作结束后 |
|---|---|---|---|
| 当前权威 | 已确认要求、规则、当前事实、有效决定、未完成现场 | 从入口找到与任务相关的来源 | 原位更新当前结论，保持路径稳定 |
| 工作材料 | 调研、候选方案、功能调整草稿、阶段计划 | 只读与正在处理的问题有关的部分 | 未决的继续保留；已结束的提炼结论，再标记替代或归档 |
| 证据 | 某版本测试结果、验收记录、资料快照 | 复核对应声明时读取 | 保留原件、版本和引用，不改写历史结果 |
| 归档材料 | 已结束且仍有追溯价值的工作材料 | 解释历史或重开决定时读取 | 保留替代去向及原因，不作为现行要求 |

这是一组使用职责，不强制迁移现有目录。一份决策日志可以同时含有效决定和被替代条目，按条目维护替代关系即可。文件的 `active` 标记、最近修改时间或名称中的 `final` 都不能自行建立权威。权威来自用户要求和项目指定的事实来源，并需要相应证据支持。

AI 从 `AGENTS.md` 和 manifest 映射开始，按具体任务展开读取；不递归预加载所有 Markdown、归档、会话总结和测试日志。搜索命中旧材料时先核对状态与替代链接，再决定能否引用。归档目录本身不能阻止工具搜索，读取纪律仍需演练验证。

## 启动条件与结束条件

由正在工作的 AI 在自然工作节点判断是否触发；本工具没有后台定时清理器。先观察触发信号，再限定整理范围，不按文件数量或存放天数自动打扫。

| 触发信号 | AI 自动做什么 | 本次整理何时结束 |
|---|---|---|
| 首次接入，或用户明确要求盘点/整理 | 只读 inventory，先找当前事实链及相关未归类材料；接入本身不授权删除已有历史 | 入口、旧材料候选和真正需要用户决定的冲突已明确 |
| 任务收尾，本轮产生/修改了方案、要求或结论 | 只检查本轮材料是否需要沉淀；没有信息变化就不写总结 | 当前来源已更新，未决项可接续，旧材料不再冒充当前依据 |
| 决定正式被替代、阶段验收或长期交接 | 收敛相关主题，检查未完成依赖，标记替代关系；范围难判断时再运行 inventory | 必要记忆与证据可找回，替代关系和受影响链接已核对 |
| 工作中读到互相矛盾的“当前”说明、再次提议已否决方案、反复翻旧材料仍找不到依据 | 暂停依赖该冲突的判断，检查相关来源与版本，按需扩大只读盘点 | 冲突已裁定并写回唯一来源，或保留明确待决项等待用户 |
| 新会话开始，但没有上述冲突 | 只读正常入口及本次任务相关来源 | 找到当前目标、现场和下一步即可，不启动全仓整理 |

整理不是独立的大工程。不要每个回合扫描全仓库，也不要为了清单好看给每份文档补标签。一次收尾只处理有触发依据的范围，未受影响的材料留在原处。

## 什么时候问用户

不确定时先区分“事实尚未查清”和“意图尚未决定”。先查看已有要求、代码、证据、决策记录与用户授权；可通过这些材料解决的归类和命名选择由 AI 完成。只有答案会改变当前要求、保留内容或授权边界，且现有材料不能裁定时才提问：

- 两份有效要求相互冲突，没有确认过的替代关系；不能用日期较新或内容较长代替用户选择。
- 计划压缩或移出的内容可能含独有用户约束或未决承诺，无法确定它是否仍然有效。
- 拟删除内容的必要性已检查，但删除超出现有授权；先形成具体文件及去向清单，再询问这一步。

提问应给出冲突的来源、AI 已查到什么、推荐处理及其影响，让用户决定一件具体的事。例如：“旧合同要求所有导出同步完成，后来的候选方案改为后台队列，但没有采用记录。是否保留同步要求？我建议对大请求采用队列，因为测试超时；这会改变调用方获取结果的方式。”不要问“这些文档哪些有用”或让用户重新分类整个仓库。

已经授权的普通归类、读取、补链接和可逆整理无需逐项再问。等待回答时保留相关原文及待决状态，只暂停依赖该答案的动作，继续处理独立事项；没有回复不视为同意。不重复追问同一个已记录的待决项，除非后续任务确实需要答案或出现新证据。

## 压缩必须保住什么

压缩是从过程叙述中提取下一次决策所需的信息。至少检查：当前结论、适用范围和用户约束、关键原因及否决选项、仍未解决的问题、对应版本的证据、重新考虑的条件。不能把“计划验证”压缩成“已验证”，也不能把暂时假设升级成产品要求。

例如 Codex 委派 Claude Code 做功能调整后，候选方案、派工说明、执行回执和测试输出可能描述同一项工作。收尾时：

1. 任务记录保留执行状态及回执，验收未完成就继续明确写未验收。
2. 当前状态只保留结论与任务链接；重要取舍进入决策来源，测试输出继续留在证据目录。
3. 被否决的候选方案标记替代关系，不再作为新的派工依据；未解决的限制仍留在当前交接。

下面是合成示例，数值不是工具包的产品要求：

```text
当前决定：导出改为后台任务，仅适用于超过 100 页的请求。
保留约束：不能改变用户已确认的导出格式。
原因：同步方案在 100 页测试中超时，不能只因实现简单再次选回。
证据：对应 revision 的测试报告链接；实现交付已有回执，但业务验收未完成。
未决：取消任务后临时文件是否回收，尚未验证，继续留在交接。
替代：旧同步方案的文件或决策条目链接。
重开条件：请求规模或超时约束变化后，重新测量。
```

## 标记、归档与删除

只有独立流转、可能被误当成当前依据的材料才需要头部标记。工具读取文件最开头 `---` 围住的简单字段；正文和代码示例不算文件元数据。`working` 表示正在研究，`candidate` 表示待验证选项，`superseded` 表示已被替代，`archived` 表示已结束并留存，`obsolete` 表示已确认不再适用。`active` 只表示仍在使用，不授予权威。

```yaml
---
lifecycle: candidate
topic: export-cancellation
---
```

已替代材料可以**留在原路径标记**，不必为了整齐移动文件：

```yaml
---
lifecycle: superseded
archived_reason: 同步方案在约定规模下超时，决定已收敛
superseded_by: project-os/DECISIONS.md
---
```

如有必要移动到 `docs/06_ARCHIVE/` 或项目已有归档目录，先确认结论已沉淀、没有活跃任务依赖，再更新所有受影响入口和相对链接。不要搬走 manifest 中的当前权威文件；历史证据继续保留原件。不确定用途的材料留在原处标候选或待归类，不能靠归档掩盖未决问题。

删除前检查独有内容、当前引用、未完成任务依赖、保留要求和可恢复性，并遵守已有用户授权或项目规则。可重建且无依赖的临时输出，可在已有授权内清理；不能只凭文件年龄、长度、名称、内容 hash 相同或“AI 觉得没用了”删除。完全相同的文件也可能承担不同的链接或使用职责。

## 只读盘点能告诉你什么

```text
python scripts/project_os.py inventory --target . --json
```

报告列出已映射入口、工作材料、证据、归档材料、未归类文件、完全重复候选和生命周期矛盾。分类来自 manifest、约定路径和文件头标记，**不代表 Agent 实际读过哪些文件，也不代表事实真伪**。没有机器可识别分类的正常 README 也可能进入未归类；这不是垃圾清单。

归档路径识别包括 `docs/06_ARCHIVE/`、`archive/`、`archives/`；现有自定义目录可保留，通过独立文件的生命周期标记识别。扫描跳过依赖、构建、缓存目录和链接路径，具体范围见报告。工具不做语义去重、不检查所有引用、不自动移动或删除，因此报告不能作为“可以删除”的证明。

## 用户怎样验收

按 [治理试验](../03_DELIVERY/GOVERNANCE_TRIAL.md) 的“文档收敛”挑战，让没有本轮聊天的新 AI 只凭整理后的正常入口回答：现在采用什么、哪项问题仍未解决、为什么没有采用旧方案。三项都能回答并找到依据，才说明这次整理保住了必要记忆。

用户只需看一段简短回执：本轮收敛了什么，未决问题是否保留，新会话接手是否实测，以及是否有待用户判断的内容。若记录了前后读取文件数或字节数，它们只表示该次演练的读取量，不等于模型 token 消耗或长期效率收益。
