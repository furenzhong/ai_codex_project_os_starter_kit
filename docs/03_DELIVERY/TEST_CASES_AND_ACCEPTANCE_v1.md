# 母仓库验收标准

版本：v1.3。适用于本 starter kit 的部署和治理能力，不是任意子项目的业务验收标准。当前实际执行结果只在当前状态引用的证据中记录；本文描述应检查什么。

## 发布要证明什么

用户把仓库链接交给 AI 后，AI 能在正在开发的项目中识别已有规则、状态、交接与决策，补齐缺口并继续使用原入口。治理效果取决于能否正确接手、限制错误完成声明和恢复中断，而不取决于模板数量。

## 必要检查

| 编号 | 场景 | 通过条件 |
|---|---|---|
| DEP-1 | 已有项目适配 | plan 显示目标与拟变更；已有权威文档映射后原字节保留；不替换业务代码、不重新初始化仓库、不复制母版状态为业务事实 |
| DEP-2 | 缺少治理的新项目 | apply 生成最小来源与映射；入口可达；未知信息保留未知；没有为填模板臆造产品和验收结论 |
| DEP-3 | 重复安装与局部配置 | 对同一目标再次 plan/apply 不覆盖既有成果、不生成第二份同义状态；自定义路径按映射读取 |
| REF-1 | 入口与引用 | check 能读取映射；缺失来源、无效相对路径与不一致任务回执得到具体诊断 |
| TASK-1 | 有据交付 | 合法 submitted 回执可检查；accepted 缺回执、验收者或验收证据不能通过相应检查；Git 对象及基线关系按实现检查 |
| READ-1 | 新会话盲接 | 无当前聊天历史的接手者从正常入口找到正确下一步，引用正确事实且不重做已有交付 |
| READ-2 | 冲突及缺证据 | 接手者不会以旧记录覆盖当前来源，也不会把未验收升级为已验收；无法判定则指出真正缺口 |
| RES-1 | 中断续接 | 隔离演练中先查任务、会话／检查点和已有回执，不因超时或缺最终答复直接重复执行 |
| CTX-1 | 上下文一致性 | 快照被改、版本／身份引用错误、纠偏缺证据、旧版本直接验收得到诊断；旧任务兼容并显示未覆盖新协议 |
| CTX-2 | 接力方向 | 无历史的负责人识别待送达纠偏和过期交付，找回硬约束，具体划定受影响工作；运行未知时不重派，不启动清理 |
| COST-1 | 维护负担 | 样本中能记录接手时间、重复劳动、用户纠偏与维护成本；没有数据时标未观察，不声称收益已证实 |

脚本检查、独立会话挑战和真实使用观察分别留证。挑战的具体输入、期望行为与操作方法见[治理试用](GOVERNANCE_TRIAL.md)；任务和回执字段见[执行合同](../02_TECH/HARNESS_CONTRACT.md)。

## 检查范围

自动化测试应验证安装幂等、保留已有文件、路径边界、任务与证据缺失等会产生实际错误的行为。文档小修只需相关链接、内容和 diff 检查，不堆叠复述实现的测试。

运行 `python scripts/project_os.py check --target PATH --json` 只证明工具检查的结构、声明与引用；它不运行验收命令，不验证语义正确、证据真实性或项目业务质量。记录 `check` PASS 时必须同时列出哪些盲接／恢复／真实使用项目仍未测。

隔离副本演练不能表述为真实生产恢复成功。首次安装和结构大改做挑战，后续仅在新改动、失败或未解疑点需要时复测相关项。用户不负责逐次给治理打分，AI 负责留证并给简短结论。
