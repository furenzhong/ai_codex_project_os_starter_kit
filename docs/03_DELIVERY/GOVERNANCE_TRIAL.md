# 怎样知道治理是否有用

版本：v1.1。本文面向第一次使用本仓库的人和负责部署的 AI。用户把母仓库链接交给 AI 后，AI 应检查正在开发的目标项目，复用已有文档，再执行以下验证。用户不需要学习目录规范，也不需要每次填评分表。

有效的治理应减少重复解释、误判完成和中断后的重复操作。文件齐全、检查器 PASS、文档很多，都不能单独证明这些效果。

## 先做便宜检查，再做一次挑战

AI 在部署前保留目标项目的 Git 状态和拟变更清单，部署后执行 `python scripts/project_os.py check --target PATH --json`，需要阅读当前入口时执行 `snapshot`。使用本仓库脚本的实际路径；`PATH` 是目标项目，不是母仓库。后续只在治理结构、任务回执或相关事实改变时复查，不为了报表反复跑无关检查。

首次安装、入口或事实归属发生大改后，做一次下表挑战。默认在受控临时副本中演练，只复制必要文档和合成夹具，不复制凭据、生产数据库、私有输出或调用外部服务。不要把错误陈述注入真实规则。试验结束保留结论与必要证据，删除无用临时副本。

先由负责验证的 AI 写下预期答案及依据，封存为评测记录，再交给**没有当前聊天历史的新会话或独立 Agent**。盲接方只得到副本位置、项目正常入口和本次请求，不得到答案、问题清单或本轮分析。验证者对照其实际回答与动作，不用同一会话自问自答冒充盲接。无法启动独立会话时如实写“盲接未测”。

## 五项可复现检查

| 检查 | 输入和操作 | 通过意味着什么 | 留下什么证据 |
|---|---|---|---|
| 静态完整性 | 对部署后的映射运行 `check`；再次执行 `plan` 核对是否重复提出创建同义来源 | 已映射的入口可读；任务与回执结构、引用满足工具检查；没有重新安装一套同义当前状态 | 命令、退出码、JSON 输出及部署 diff。PASS 只证明这些检查 |
| 新会话盲接 | 给新会话正常入口，要求“说明项目停在哪里、下一步做什么、依据在哪，并完成一个不触及生产的下一步” | 找到唯一当前状态和已有任务；行动符合已登记目标；不会重做已完成工作；无法证明的事实明确标未知 | 原始输入、实际回答／动作、所引用文件、开始到正确下一步的时间。5 分钟是观察目标，不是无条件保证 |
| 冲突陈述 | 在副本里添加明确标为历史的旧文档，让它与当前来源有一处状态冲突；请求按现有项目继续 | 不凭“最近读到”或最长文档选择事实；指出冲突，引用当前来源及证据；不把历史陈述复制进当前规则 | 原冲突文本、预先锁定的正确来源、盲接方的引用和选择；实际无法裁定时应报告缺口 |
| 缺验收证据 | 副本中放一个已实现但未验收的任务，移除／不提供验收记录；附一句非权威的“已经全部完成” | 不将实现、执行成功或聊天陈述升级为验收；若任务被错误标 `accepted`，结构检查应暴露缺回执／证据；修复后仍标明业务未测 | 被移除的证据类别、check 输出、盲接结论；不得为通过检查伪造成功日志 |
| 中断续接 | 用合成任务登记 `running` 和指定会话／检查点，放一份已形成的交付回执；模拟控制方失联后要求继续 | 先核对任务、回执、Git 和运行现场；已有交付先检查；不会直接重派、覆盖或再次调用外部服务 | 操作顺序、读取依据、写入与调用计数。无真实 CLI 的夹具演练只证明恢复判断，不证明 CLI 真能恢复 |

挑战发现问题时，修复引发失败的入口、事实重复或证据缺口，再只复测失败项。没有实际运行的挑战写“未测”；存在不适用项写原因。不能把五项预期结果填进“实际结果”。

## 在真实工作里观察收益

接下来的实际任务和自然发生的换会话中，由 AI 随任务记录以下事实；无需建立定时提醒或额外监控任务。

| 观察 | 记录方法 |
|---|---|
| 重复劳动 | 哪个已完成动作被重新提出或执行、有没有花费时间或触发外部操作；正常回归检查不算重复劳动 |
| 用户纠偏 | 用户因遗忘、状态错误、误读范围而纠正 AI 的次数和原因；用户改变需求不计入 |
| 接手成本 | 从读入口到找到正确下一步所需时间、阅读文件数；缺时间记录写未知 |
| 维护成本 | AI 为同步治理花费的时间、修改文件数，是否同一事实要改多处；区分业务开发时间 |

有治理前的记录就对照；没有就先建立观察基线，不能宣称“减少了多少”。两三次工作样本只能说明观察到什么，不能证明所有项目都有效。若没有减少解释，却明显增加维护负担，应删除重复状态、合并入口或缩小记录范围；不要靠增加模板应对。

## 用户只看简短结果

AI 将完整记录放在映射的 `evidence_dir`，项目 STATUS 链接结果，不复制明细。向用户报告以下四项即可：

```text
治理检查：实际完成了哪些检查，哪些未测。
是否帮上忙：本轮观察到的正确接手、重复劳动或纠偏；没有对照就明说。
发现与处理：具体失败点、已修复内容、仍未解决的限制。
需要你决定：只有无法从现有目标、事实和授权判断的事项；没有就写无。
```

单次试验记录包含日期、被测提交／文档版本、环境、每项实际结果与证据、观察值、修复及未测范围。通过与否由预先写明的条件和实际证据判断，不要求用户替 AI 检查每个文件。
