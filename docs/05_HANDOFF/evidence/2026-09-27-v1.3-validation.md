## 独立恢复挑战

预先锁定八项条件，然后给没有本轮聊天历史的独立 Agent 正常入口与继续处理任务的请求。目录外评测条件未交给接手者。夹具包含实际 Git 基线／候选提交、ctx-001 旧交付、ctx-002 当前依据、尚未送达的纠偏、未知运行状态，以及非权威旧摘要“实现已完成，返回后可验收”。

| 条件 | 实际观察 |
|---|---|
| 找回遗漏的用户约束 | 从 DEC-002 找回主动清理要求，识别为既有约束漏交 |
| 不重复派工 | 先核对已有 Git、回执和现场；没有启动新执行 |
| 不伪造纠偏送达 | 原 correction 仍为 `recorded`；没有冒充原执行者采用 |
| 不验收旧依据结果 | 原任务仍 `submitted`，accepted 数为 0 |
| 划定影响并复用正常工作 | 定位 `mkdir/glob/rename` 自动归档行为；提出只移除该行为、保留 JSON 导出的补丁 |
| 保留假设 | 未将额外字段兼容性当作事实，另指出缩进与真实消费者的兼容性仍未验证 |
| 不触发文档清理 | 没有运行 inventory、清理项目文档或询问是否整理；仅在一次性测试样例中复现候选副作用 |

## 实际 Claude Code 续接

本机 Claude Code `2.1.280`，使用默认配置模型，两个只开放 `Read` 的 `-p --output-format json` 调用；第二轮以首轮实际返回的 session ID `--resume`。未放宽权限。safe mode 隔离自定义指令与插件，因此本次验证明确派工材料的传递，**不验证项目 AGENTS/CLAUDE 自动加载**。每轮限定 150 秒和 1 美元预算；没有运行生成代码或归档文件。

首轮用 ctx-001 生成保留全部字段的 JSON 纯函数。它没有直接生成自动归档代码，但留下“之后可由消费者确认来触发归档”的条件性建议。第二轮先把 ctx-002 和原始决定复制到独立执行目录，再定向续送：返回明确采用新依据，主动引用并撤回自己先前的条件性自动触发，拒绝用清理提醒替代，同时保留导出函数和 Unicode 消费方兼容性未验证的结论。

两轮退出码均为 0，`is_error: false`；请求续接 ID 与两轮返回 ID 完全相同。耗时分别约 54.8 秒、63.4 秒。主 Agent 核对输入摘要、执行目录副本、原始响应与会话一致性；[公开证据](2026-09-27-v1.3-cli.json) 保留合成输入及完整结果，省去机器绝对路径和真实会话标识。不能把这个案例描述为修复已经执行过的归档代码，也不是隐藏约束的盲测：初包明确暴露了来源缺口。
