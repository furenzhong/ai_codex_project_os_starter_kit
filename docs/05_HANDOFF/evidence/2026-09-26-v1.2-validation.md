## 独立接手与提问边界

采用两个独立、无当前聊天历史的 Agent。派发前锁定夹具与预期；Agent 只得到隔离项目路径、AGENTS 正常入口和普通只读接手请求，没有收到预期答案。输入、预期、回答转录与读取路径见 [完整演练记录](2026-09-26-v1.2-lifecycle-trial.json)。夹具的规则由本版安装器产生，所列业务内容全部是合成数据。

1. 已收敛案例：正确沿用大请求后台队列、小请求同步及 PDF 约束，保留取消回收未验证项；追溯到同步基准 42 秒超过 30 秒预算的否决原因，没有把历史基准当作当前验收。没有重新询问已确定的产品要求；额外提出了进入实际开发前需要业务代码位置的条件性问题，未阻塞本次只读判断。
2. 真实意图冲突案例：两份同日确认、无替代记录的合同要求不同。Agent 询问适用范围及最终效力，说明调用协议影响；没有以性能数据自行指定合同优先权，保留原文与未决项，并指出可继续的独立检查。

两个夹具的 Markdown 在接手前后字节内容保持一致。这里验证的是整理后信息的可接续性和提问判断，没有测试 AI 自动压缩真实长文档，也没有跨模型 CLI 调用。读取路径由执行者报告，未建立前后对照或 token 度量，不能由此宣称节省多少上下文或长期维护成本。

## 边界

inventory 只读，不做语义去重、引用完整性验证、自动归档或删除。它也不能阻止其他工具读取历史文档。触发机制由工作中的 AI 执行规则，不是后台监控任务。长期效果仍需真实项目中的自然换会话、用户纠偏与维护负担记录。

远程验证使用本次发布提交对应的 [GitHub Actions](https://github.com/furenzhong/awoo-vibe-coding-governance/actions/workflows/check.yml)，矩阵为 Ubuntu / Windows × Python 3.10 / 3.14；不能用旧版本的绿色结果代替本次运行。
