## 需要保留的现场

| 现场信息 | 实际值或证据 |
|---|---|
| 工作目录与基线 | [优先链接任务记录，避免再次抄写 SHA] |
| 未提交改动 | [文件、归属和用途；没有写无] |
| 仍在运行的进程或会话 | [链接任务中的会话与运行证据；未知就先核对] |
| 已形成但尚未处理的产物 | [回执／检查点／交付路径] |
| 待送达或待采用的纠偏 | [链接任务中的纠偏记录；已写文件不等于对方已收到] |
| 继续前必须核实的事 | [真实不确定项；没有写无] |

不记录凭据或敏感响应。中断后先查这些现场和实际运行状态，再恢复明确会话／检查点，不能因为上一轮没有最终回答就重新执行。检查点是上次观察，不证明进程现在仍运行或已经停止。

采用 [任务上下文协议](../../02_TECH/TASK_CONTEXT.md) 时，负责人和各执行身份分别维护自己的检查点，不轮流覆盖共享 HANDOFF。检查点区分已完成动作及结果、未决假设、运行操作与定位信息、下一步，并引用实际采用的上下文版本。收到旧版本交付时先核对纠偏与受影响范围，不能直接验收。

## 交接更新

只在有意义的停点或现场变化时更新；派工、实质选择和纠偏记录回各自的任务文件。规则、目标、状态、问题表和完整日志不在这里复写；需要它们时添加相对链接。没有独立交接现场的简单任务，保留 STATUS 与任务入口即可。旧任务没有检查点时据真实现场恢复，不补造历史。

交接维护不启动文档盘点、清理、合并或归档，也不因此询问用户是否整理；这些操作仍只在用户主动请求后进行。不要求每轮总结，不依赖压缩前钩子。
