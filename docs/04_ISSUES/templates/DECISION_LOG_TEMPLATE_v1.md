# [项目名称] 决策日志

## 1. 文档作用

这份文档用于统一记录项目中的**正式决策**，确保所有已经拍板的重要结论都具备：
- 唯一标识
- 明确背景
- 明确结论
- 明确影响范围
- 明确替代方案
- 明确后续动作
- 可被未来的 AI / Codex / 协作者追溯理解

它的目标不是记录“讨论过程”，而是记录：

**最后我们为什么这样定。**

---

## 2. Decision Log 和其他文档的关系

### 与 Tech Question Register 的关系
- `ISSUE_TECH_QUESTION_REGISTER.md`：记录问题、分析、待拍板状态
- `DECISION_LOG.md`：记录已经形成的正式结论

### 与 Bug Register 的关系
- `Bug Register` 记录“哪里坏了”
- `Decision Log` 记录“因此我们决定怎么做”

### 与基线文档的关系
`Decision Log` 本身通常不是最终执行规范，而是：
- 为基线文档提供决策依据
- 为新 AI 提供历史理由
- 为未来重构或复盘提供背景

---

## 3. 什么应该进入 Decision Log

### 应记录的决策类型
- 产品边界决策
- 架构决策
- 数据结构决策
- 规则策略决策
- 开发治理决策
- 风险规避决策

### 不建议写入 Decision Log 的内容
- 普通 bug 修复记录
- 纯执行性工作记录
- 尚未拍板的想法
- 一次性临时说明
- 无长期价值的小调整

---

## 4. 决策状态规范

### 状态枚举
- `active`
- `superseded`
- `deprecated`
- `archived`

## 8. 决策替代规则

当旧决策被替代时：
- 将旧决策状态改为 `superseded`
- 写明新的替代决策 ID
- 在新决策中写明“替代了谁”
