# 实现结构

## 持久知识

目标和验收条件保存在项目合同；当前事实、现场和决策分别由 manifest 指向的文档维护。索引不另存状态。任务与回执记录可定位的一次执行及其证据。

## 可重复工具

`scripts/project_os.py` 使用 Python 标准库，无网络调用和模型依赖。

- `plan`：读取源与目标，列出新增、追加、复用和冲突。
- `apply`：在冲突检查通过后执行增量接入；不替换目标 Git 配置或业务文件。
- `check`：核对声明的路径、入口与任务证据，输出错误、提醒和检查边界。
- `snapshot`：报告当前可观察的仓库和治理信息，不改写状态文档。

既有 shell 入口作为兼容包装，不构成独立的状态维护实现。工具的具体参数以 `--help` 为准。

## 执行协作

[Harness 合同](HARNESS_CONTRACT.md) 描述派工、写入归属、结果接回和中断恢复。工具只核对可机械判断的部分，不启动 Codex 或 Claude Code。验证者负责核查证据是否足以支持验收结论。

## 版本边界

源工具包有版本和 Git revision，目标 manifest 记录来源。已接入项目的业务规则与状态归该项目所有。apply 是幂等接入，不负责升级已有脚本或 manifest；后续升级由 AI 比较版本和文件差异后合并。受管入口与映射不符时报告冲突，现有项目内容不自动覆盖。

本轮保留轻量本地工具，不引入数据库、服务进程、模型路由或消息队列。
