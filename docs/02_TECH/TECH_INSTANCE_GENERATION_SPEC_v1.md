# 接入和实例化合同

## 身份与输入

源是提供治理资产的仓库；目标是用户要求应用治理的项目。当前 shell 目录可能属于下载源，不能据此替代用户目标。目标不清楚时先检查工作区上下文，仍不能确定再询问。

最低输入是目标目录和实际项目材料。已有 `AGENTS.md`、状态、验收记录、Git 状态都是材料。`PROJECT_BOOTSTRAP_INPUT.md` 是可选辅助，不要求用户重复填已有信息。

源目录、其 Git worktree 或同一母仓库的克隆不应成为默认业务接入目标。若用户确实在维护母工具包，按母仓库开发处理，不运行实例接入。

## 最小输出

`project-os.json` 映射 rules、status、handoff、decisions、tasks_dir、evidence_dir。默认创建四份最小文档；已有等价文档时通过 `--mapping` 引用。目标 Agent 入口只追加导航；共享规则正文不复制到两个入口。

不批量生成 PRD、接口、前后端目录，也不覆盖 README、源代码、未提交文件或 remote。文档内容由 AI 从该目标的真实材料归纳，工具生成的占位不构成项目已接入验收。

## 失败与升级

路径冲突、越界或身份不符时，工具返回原因，AI 应调整映射或处理具体差异；禁止以删除目标、重新初始化 Git 或 force 覆盖解决。已授权的普通补写和映射选择不需要反复询问。

重复运行保持用户已有内容。更新源版本不代表目标自动升级完成；先生成差异，分别处理工具代码、稳定规则和项目自己的事实。

## 验证

检查目标原有文件与 Git remote 保持原样、新入口能找到真实事实、空白内容已标明未知；再进行 [治理试验](../03_DELIVERY/GOVERNANCE_TRIAL.md)。机器检查和 AI 行为检查分别记录。
